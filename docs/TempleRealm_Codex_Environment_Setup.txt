6. AUTONOMOUS VALIDATION AND ANDROID LIMITS

An initial native attempt does not require changing the game. After the install,
Java and rendering checks above, run this focused source-matched smoke test:

  cd /workspace/3d-open-world-game-
  source tools/common.sh
  python tools/build_emulator_apk.py
  python -u tools/test_android_runtime.py

The runtime checker returns 0 for PASS, 2 for BLOCKED and 1 for FAIL. Preserve and
report that outcome. It owns/cleans its emulator and isolated adb server. Diagnose
errors before a bounded retry; a blocked native check is not a full Android pass.

Use tools/autonomous_cycle.sh --runtime auto after a meaningful game change. It
runs gameplay, security, real rendering, the signed phone APK, emulator setup,
a separate source-matched x86_64 emulator APK and bounded native runtime checks.
The phone build stays ARM64; the emulator build changes only the export ABI.

auto can report PARTIAL for a proven host-only runtime block. Application failures
remain failures. --runtime required keeps native validation strict. --runtime skip
is an explicit partial host-only check, not full Android validation. Preserve the
foreground, readable-HUD, camera-input and app-local-save assertions.
